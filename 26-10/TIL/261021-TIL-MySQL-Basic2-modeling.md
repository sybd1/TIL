## [2026-10-21] MySQL DDL, constraints, data types, index, Modeling

### 1. 오늘 배운 핵심 개념 (What I Learned)
#### DDL (Data Definition Language)
- 데이터 정의 언어 (CREATE, ALTER, DROP)
- 테이블 구조를 직접 정의하는 기능. DML과 다르게 DDL은 작업 도중에 커밋이 발생하여 롤백을 하기 어려움이 있다.


##### BASIC 용어
- VARCHAR(255): 255자의 문자열 타입.
- CHAR(3): 고정 길이 문자열 타입.
- DECIMAL(5, 2): 소수점 위아래를 합친 전체 자릿수 5, 소수점 아래 자릿수2라는 의미의 실수형 타입.
- DESCRIBE: 테이블의 구조를 확인할 수 있는 구문.
- EXPLAIN SELECT: SELECT문을 MySQL이 어떻게 실행할지 보여주는 구문.


##### CREATE
- CREATE TABLE IF NOT EXISTS/ENGINE=INNODB: 테이블 생성 구문.
    - IF NOT EXISTS: 존재하지 않을 때만 생성하기 위한 구문.
    - INNODB: MySQL의 대표적인 엔진.
- AUTO_INCREMENT: 해당 하는 컬럼에 순서대로 숫자를 1씩 증가 시켜주는 구문. 보통 PRIMARY KEY와 함께 사용한다. 이 구문을 사용한 컬럼에는 NULL 값이나, 값을 생략해도 자동으로 번호를 생성한다.

##### ALTER
- 테이블에 추가/변경/수정/삭제하는 모든 것은 ALTER 명령어를 사용해 적용한다.
- ALTER TABLE/ADD : 컬럼 추가.
- ALTER TABLE/DROP COLUMN: 컬럼 삭제.
- ALTER TABLE/CHANGE COLUMN/change_: 이름과 데이터 타입을 함께 변경.
- ALTER TABLE/MODIFY: 데이터 타입 변경.

##### DROP
- DROP TABLE IF EXISTS: 테이블 구조와 데이터를 영구적으로 삭제.
- TRUNCATE TABLE: 테이블 구조는 남겨두고, 데이터만 초기화.

#### Constraints (제약 조건)
##### NOT NULL
- NOT NULL: 해당 컬문에 NULL 값을 허용하지 않음. NOT NULL 값을 걸어둔 컬럼에 NULL을 추가하려고 하면 에러를 일으킨다.

##### UNIQUE
- UNIQUE: 해당 컬럼에 중복 값을 허용하지 않는다. 값이 중복되면 에러가 난다.

##### PRIMARY KEY
- PRIMARY KEY: 테이블의 각 행을 대표하는 키를 만들어 식별자 역할을 한다. NOT NULL, UNIQUE를 동시에 사용한 것과 기능이 동일하다. 한 컬문에 사용할 수도 있고, 다른 여러 컬문에도 사용할 수 있다.

##### FOREIGN KEY
- FOREIGN KEY: 두 테이블을 연결하고 관계를 맺어준다. 참조된 다른 테이블에서 제공하는 값만 사용할 수 있다. 제공되는 값 외에는 NULL을 사용할 수 있다. FOREIGN KEY/REFERENCES 키워드는 자식 테이블이 부모 테이블의 제약 조건을 참조해서 작성할 수 있다.

#### Data Types 명시적 형변환
- CAST/AS SIGEND 타입: SELECT 구문의 컬럼을 소괄호로 감싸는 문법으로 명시적 형변환을 할 수 있다.
- CONVERT: CAST 문에서 AS대신 쉼표를 사용하는 문법. 표기법만 다른 명시적 변환.
    - SIGNED INTEGER: 부호가 있는 정수, 즉 음수, 0, 양수를 표현(INTEGER는 생략 가능)
    - UNSIGNED: 부호가 없는 정수.
- 암시적 형변환
    - SELECT '1' + '2'; // 3
    - SELECT 3 > 'MAY'  // true

#### Index
- 방데한 데이터를 찾을 때 조회 속도에 도움을 주는 기능이다.
- CREATE INDEX/ON: 인덱스 생성하는 구문. INDEX를 생성하면 데이터베이스가 이름을 더 효율적으로 찾을 수 있도록 별도의 탐색 구조를 만들어 활용한다. INDEX를 무작정 많이 만들면 저장 공간이 그만큼 많이 필요하고, 데이터를 추가, 수정, 삭제할 때 인덱스도 관리해야 하므로 적절하게 필요한 테이블의 컬럼에 사용하는 것이 좋다.
- SHOW INDEX FROM: INDEX를 찾아볼 수 있는 문법.
- DROP INDEX/ON: 인덱스 삭제하는 구문.

#### Modeling
- 데이터 베이스를 목적에 맞게 만들기 전에 복잡한 구조를 모두가 알아보기 쉽게 설계도 구상. 복잡한 현실 세계를 단순화, 추상화, 명확화하여 일정한 표기법으로 표현하는 작업.
- 건축물이 복잡해질수록 설계도가 중요해진다. 시스템 구축 시 이해관계자 간의 의사소통, 시뮬레이션, 문제 해결, 핵심 파악, 연구/개발의 기준이 된다.
    - Simplification (단순화): 선택과 집중을 통해 필요한 것만 추려낸다.
    - Abstraction (추상화): 다양한 현상을 일정한 표기법으로 묶어 표현한다.
    - Clarity (명확화): 애매모호함을 없애고 누구나 동일하게 이해하도록 명확히 기술한다.
- 관계형 DB (RDBMS): 데이터 분류/관계 명확화, 중복 제거, 무결성 보장. 초기 구조 설계(데이터 모델링)가 필수적이다.

- 정보 시스템 모델링의 3대 축
```1. 데이터 관점: 무엇을 별도 테이블로 관리할 것인가?```
```2. 프로세스 관점: 각 테이블에는 어떤 값을 저장할 것인가?``` 
```3. 상관 관점: 테이블과 테이블은 어떻게 연결되는가?```

##### ERD Notations 표기법
- ERD (Entity Relationship Diagram) 개체-관계 다이어그램: 데이터베이스에 어떤 테이블이 있고, 테이블들이 서로 어떻게 연결되는지 그림으로 표현한 것.
- Baker 표기법: 오라클/데이터 아키텍처 전문가에서 선호. 베타적 관계나 슈퍼-서브타입을 박스 안에 중첩하여 직관적으로 표현.
- IE 표기법: 까마귀 발 표기법으로 널리 알려진 실무 범용 표기법.

#### Relational Model 관계형 모델
- Relation (릴레이션): 테이블 전체
- Attribute (어트리뷰트): 컬럼
- Value (어트리뷰트 값): 컬럼 값
- Tuple (튜플): 행
- Identifier (식별자): 튜플을 구분하는 값
- Cardinality (카디널리티): 튜플의 수
- Degree (디그리): 어트리뷰트의 수


#### Entity와 Attribute
- Entity: 업무 관심 대상이 되는 유/무형의 정보 단위(개체).
    - 도출 원칙: 
        - 반드시 업무상 관리해야 하는 관심 대상이어야 한다.
        - 2개 이상의 인스턴스(행)를 가져야 한다. (인스턴스가 1개뿐이면 엔티티가 아니다.)
        - 인스턴스를 유일하게 식별할 수 있는 식별자가 존재해야 한다.
        - 고유한 성격을 지닌 1개의 독립된 주제여야 한다.

#### Identifier (식별자)
- Identifier
    - Primary Identifier (주식별자)의 4대 조건
        - 유일성: 모든 인스턴스를 고유하게 식별.
        - 최소성: 유일성을 보장하는 최소한의 속성으로만 구성.
        - 불변성: 식별자 같은 한 번 정해지면 변경되지 않아야 함.
        - 존재성: 절대 NULL이 올 수 없음 (NOT NULL).
        - FOREIGN KEYM Foreign Identifier (외래식별자): 부모 엔티티의 주식별자를 자식 엔티티가 참조하기 위한 연결 고리.

#### 관계의 구성 요소
```
[부모 엔터티] ------------< (카디널리티: 1:N)
             |          |
        [옵셔널리티: 필수/선택]
```

1. **카디널리티 (Cardinality)**: 인스턴스 간 매핑 비율 ($1:1$, $1:N$, $M:N$).
   > ⚠️ **$M:N$ 관계**는 실무 DB에서 직접 구현할 수 없으므로, **교차 엔터티(Association Entity)**를 생성하여 **두 개의 $1:N$ 관계로 해소**해야 한다!
2. **옵셔널리티 (Optionality)**:
   - **Mandatory (필수, `|`)**: 반드시 최소 1개 이상 존재해야 함.
   - **Optional (선택, `O`)**: 없어도 됨 (0개 이상).
3. **관계 디그리 (Degree)**: 관계에 참여하는 엔터티의 수 (1항: 재귀, 2항: 이항, 3항 이상: 다항).
- **배타 관계 (Exclusive Relationship)**: 여러 상위 엔터티 중 **오직 1개와만 배타적으로 관계를 맺음** (예: 회원이 일반 고객이거나 임직원 중 하나에만 속함).


##### Integrity (데이터 무결성) vs Consistency (정합성)
- Integrity: 데이터가 정확하고 완전하며 유효한가?
- Consistency: 데이터 간에 모순이 없고 서로 일치하는가?
- 모든 데이터가 통일되게 틀린 값으로 채워져 있다면 정합성은 맞지만 무결성은 깨진 상태.

##### 데이터 무결성의 4대 종류
1. **엔터티 무결성 (Entity Integrity)**: 모든 인스턴스는 고유해야 하며, 기본키(PK)는 중복되거나 `NULL`일 수 없음.
2. **참조 무결성 (Referential Integrity)**: 외래키(FK) 값은 참조하는 부모의 기본키 값이거나 `NULL`이어야 함.
3. **도메인 무결성 (Domain Integrity)**: 속성 값은 정의된 데이터 타입, 길이, 허용값 범주, 기본값 규칙을 준수해야 함.
4. **업무 무결성 (Business Integrity)**: 기업 비즈니스 규칙과 프로세스 정책을 만족해야 함 (예: 대출 한도 규정 등).

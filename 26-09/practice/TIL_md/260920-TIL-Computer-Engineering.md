## [2026-09-20] Computer Engineering Basic

### 1. 오늘 배운 핵심 개념 (What I Learned)
#### 발단
- JavaScript에서 React로 넘어오면서 Virtual DOM이라는 개념을 배우고 넘어갔다. 이전 객체와 새로운 객체를 컴포넌트 내부에서 비교하고 가상의 DOM 공간에서 처리한 뒤 렌더링을 한다는 설명을 들었는데 잘 이해가 되지 않았다. 가상의 공간? 어디서 가상의 공간이 생기는 것이고 그것을 처리하는 것이지? 내가 작성한 코드는 어디로 가서 어떻게 작동하는 원리지? 우리가 사용하는 코드를 통해 터미널이나 웹페이지에서 작동하는 것을 알고 있었지만, 이것들이 어떻게 돌아가고 있는 것인지 나는 아무것도 파악하고 있지 않았다. 컴퓨터는 원래 클릭하고 입력하면 당연히 작동하는 전자 제품이니까. 나는 그래서 내가 배우는 이 언어들과 코드를 쳐서 작동하는 원리 그리고 우리는 왜 이런식으로 개발을 하고 있는지 역사도 찾아보았다.

#### Programing Language
- 컴퓨터에서 작동하는 모든 언어의 기본 원리는 전자신호를 키고 끄는 것에서 시작되었다. CPU 내부의 트랜지스터 전원이 켜지면 1, 꺼지면 0. 컴퓨터를 발명했을 당시에도 그랬고, 현재도 양자 컴퓨터의 0과 1이 중첩된 상태를 제외하고는 원리는 지금도 똑같다. 이 전자 신호는 정말로 0과 1뿐이라 인간이 다루기엔 적합하지 못했고, 그래서 0과 1 짧은 영단어를 결합한 첫 컴퓨터 언어 **Assembly Language (기계어)** 가 등장한다.

- Assembly Language를 통해 컴퓨터와 하드웨어들은 점점 빠르게 발전해나갔다. 하지만 이런 기계어도 여전히 직관적이지 못했고 하드웨어를 다루기 어려웠다. 그래서 사람들은 이 기계어를 토대로 인간의 언어와 흡사한 영어 단어로 언어를 만든다. 그 언어가 **C Language**이고 하드웨어를 직접 제어할 수 있는 강력한 언어의 탄생이었다.

- 이후에 사용하던 언어의 길이가 점점 길어지고 읽기 힘들어지면서 사람들은 생산성, 유지보수성, 작업 효율 등을 따지며 수많은 언어들이 시대에 맞춰 탄생하게 된다. C++, python, java, JavaScript, C# 등 다양한 언어가 출시됐다.

        내가 배운 HTML은 Markup Language, CSS는 Style sheet Language이다. 실제 언어는 JS뿐이다.

- 그런데 약간의 문제가 있다. 처음 말했듯이 컴퓨터는 처음 발명됐을 때도 그렇고 현재도 0과 1의 신호만 알아들을 수 있다. 그러므로 하드웨어는 이 모든 언어들을 알아들을 수가 없다. 그래서 사람들은 이 언어를 하드웨어로 번역할 수 있는 새로운 방식을 도입했다. 그것이 바로 **Engine(엔진)** 이었다.

- 사실 새로운 언어들과 엔진으로 지금 여기까지 대AI시대가 범람했지만, 항상 이득만 취할 수 있는 것은 아니다. 언어가 늘어나고, 그 언어를 번역하는 시간과 방법이 많아지면서 하드웨어는 일이 늘어났다. (물론 소프트웨어가 성장하는 속도에 맞춰서 하드웨어도 지금까지 큰 문제없이 잘 발전했다.) 이렇게 기계의 처리속도를 일부 희생하는 대가로 인간의 일의 능률을 극대화하는 전략적 교환을 **Trade-off** 라고 한다. 그리고 더불어 복잡하고 하드웨어를 직접 다룰 수 있는 언어를 하부 계층으로 숨기고, 상부의 직관적이고 쉬운 문법을 다룰 수 있게 덮어 씌우는 설계 기법을 **Abstraction(추상화)** 이라고 한다. 내가 지금까지 사용한 모든 언어들은 몇 번의 추상화를 거친 언어들이다.
- 현대 거의 모든 전자제품은 Trade-off와 Abstraction 방식으로 만들어졌다. 
지금 내가 배우는 React로 예를 들면, 이용자가 React를 기반으로 만든 웹사이트에서 무언가 클릭한 상황이다. (React의 JSX 문법의 코드는 Transpiler(구문변환기) Babel이 코드를 작성하고 저장한 시점에서 이미 JS언어로 번역을 해둔다.)
1. 사용자가 마우스로 반응하여 입력된 값은 전기 신호로 곧장 하드웨어로 도착해 신호를 내보내고, OS가 이것을 포착해 좌표 값을 브라우저에게 넘겨준다. 브라우저는 다시 이 좌표값에 있는 HTML 요소의 이벤트를 발생시킨다.
2. React로 적은 코드의 로직이 실행된다. vDOM의 비교 연산으로 변경된 값을 찾아내 real DOM에게 주입한다.
3. 나중에 이야기할 엔진, 크롬 브라우저의 심장부 V8엔진이 이 추상화 된 텍스트 코드들을 번역하여 0과 1의 신호를 CPU에게 보낸다. CPU는 빛의 속도로 트랜지스터의 스위치를 열고 닫으며 계산을 마친다.
4. CPU는 계산된 값을 브라우저 렌더링 엔진에게 Reflow(재계산)을 시키고, GPU에게 그 좌표에 픽셀을 칠하라는 명령을 내린다. 그렇게 GPU는 모니터 화면에 색깔이 바뀌거나 버튼이 클릭되는 이벤트가 사용자가 볼 수 있는 형태로 일어난다.

#### Engine
- Engine은 쉽게 설명하면, 우리가 작성한 코드들의 언어를 하드웨어가 알아들을 수 있게 번역해주고 받은 값을 처리하는 역할을 한다. 언어를 번역할 엔진이 없다면, 우리가 작성한 언어의 코드들은 실제로 txt 텍스트 파일과 물리적으로 완벽하게 동일하다. 
- 엔진은 크게 4가지의 Module로 작동한다.
    - Parser: 텍스트로 된 코드를 컴퓨터가 조작하기 쉬운 Tree형태로 변환한다.
    - Execution Unit (Compiler, Interpreter): Parser가 넘겨준 데이터를 번역하고 실행한다. 특정 언어를 지정해 Compiler, Interpreter를 적재적소에 잘 사용하는 것이 엔지니어의 핵심역량(Architecture)이다.
    - Memory Manager(Heap, Call Stack): Execution Unit이 쓸 데이터를 RAM의 Heap(데이터 창고)에 할당하고, 함수의 실행 순서를 Call Stack(호출 기록장)에 기록하며 다 쓴 데이터는 Garbage Collector가 삭제한다.
    - Bindings: 번역된 결과물을 엔진 바깥 브라우저나 운영체제에 전달한다.
- Compiler: 프로그램을 실행하기 전에 인간이 작성한 전체 코드를 처음부터 끝까지 마치 책처럼 한 번에 0과 1의 기계어로 통번역을 하여 새로운 실행파일을 만들어 둔다. (C, C++, RUST, GO 등 하드웨어 제어와 속도가 중요한 언어들이 이러한 형식을 취하고, 주로 백엔드 서버, 게임, OS 기능에 사용한다.)
- Interpreter: 코드를 미리 번역해두지 않고 프로그램이 실행되는 그 순간순간마다 코드를 한 줄씩 실시간으로 0과 1의 기계어로 번역하여 하드웨어에게 명령을 내리는 방식이다. (Python, Ruby, 초기JS 등 개발 편의성과 유연성이 중요한 언어들이 이러한 형식을 취하고, 주로 웹 브라우저, 프론트엔드 환경에서 사용한다.)


#### 공부하고 내린 나의 생각
- 내가 배운 React도 vDOM도 새 메모리를 할당하면서 비교연산으로 JSX 문법까지 더 해 계속 복잡한 과정을 추가해서 작업한다. **인간의 시점에서나 효율적이게 작업하는 것이지, 차가운 하드웨어 입장에선 이 방법이 전혀 효율적이지 않다.** 지금까지는 인간의 편의성과 능률을 위해 새로운 언어들과 엔진이 개발되었지만, 근간인 0과 1의 전기 신호 보다는 어쩔 수 없이 하드웨어에 주는 부하가 크다는 것을 알게되었다. vDOM 가상의 공간, 그 궁금증으로 여기까지 공부했다.
- 아직 AI는 인간이 추상화해서 사용하는 이런 쉬운 언어들조차 정복하지 못 했지만, 그 속도가 하루하루 갈수록 너무나도 빠른 것이 체감된다. 그리고 언젠가 AI가 코드를 정복하는 날이 온다면, 그것은 우리가 현재 사용하는 추상화 된 언어가 아닐 거라는 생각이든다. 아마 가장 속도가 빠르고 메모리를 적게 차지하는 0과 1의 전기 신호로만 코드를 작성할 것이다. 인간은 그렇게 코드를 짜는 것이 도저히 불가능하기 때문에 수많은 Abstraction과 Trade-off 방식을 거쳐서 여기까지 왔지만, AI는 이해하는 것이 아니라 단순하게 0과 1의 수천억 줄의 신호를 만드는 것이 가능할 것이다. 모순적이게 결국 우리가 만든 모든 언어는 도태되어 구시대의 산물이 되고 AI에게 0과 1의 전기 신호를 맡기는 세상이 올 것 같다.

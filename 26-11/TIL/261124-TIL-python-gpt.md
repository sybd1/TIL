> Attention: 문장에서 어디를 볼지 정하는 장치이다. 인공지능은 단순히 단어 하나가 아닌 문장 전체의 연결고리를 계산한다. 이때 사용되는 핵심 기술이 어텐션이다. 트랜스포머 구조의 핵심 요소.
> Transformer: Attention을 쌓은 구조이다. 이전의 RNN은 단어를 하나씩 순서대로 읽어서 느렸고, 문장이 길면 앞부분을 잊어버렸다. Transformer는 모든 단어를 한꺼번에 병렬로 처리하고, 멀리 떨어진 단어도 직접 연결한다. 그래서 대규모 학습이 가능하다.

#### 인공지능
- 토큰: 모델이 텍스트를 처리하는 단위. 입력을 받으면 토크나이저가 텍스트를 여러 조각으로 나누고 각 조각을 숫자 ID로 바꾼다. 모델은 그 숫자들의 순서를 입력 받는다. 조각 하나가 토큰 하나이다. 단어 하나가 통째로 들어갈 수도 있고, 여러 조각으로 나뉠 수도 있다. 공백이나 괄호 같은 기호도 토큰에 포함될 수 있다.
- 컨텍스트: 모델이 이번 답변을 만들 때 참고하도록 전달받은 정보이다. 현재 질문, 함께 전돨된 이전 대화나 압축본, 모델에 주어진 지침, 실제로 읽어 온 코드나 도구 결과가 컨텍스트를 구성한다.
- 컨텍스트 윈도우: 컨텍스트 내용을 처리하고 답변을 만들 때 쓸 수 있는 토큰 한도이다.

##### 데코레이터
함수를 받아서 기능을 덧붙인 새 함수를 돌려주는 함수입니다. 원래 함수의 코드를 고치지 않고 앞뒤에 공통 동작(시간 측정, 로깅, 권한 검사 등)을 끼워 넣을 때 씁니다.

- with: 블록의 시작과 끝을 관리하는 문법. 파일이나 DB연결처럼 사용이 끝나면 정리해야 하는 것을 다룰 때 사용한다. f.close()를 직접 쓰지 않고 중간에 에러가 나도 정리를 보장한다.
- yield: 값을 건네주고 함수 실행을 잠시 멈추는 키워드. return은 값을 반환하면 함수가 끝이나지만, yield는 값을 주고 그 자리에서 잠깐 멈췄다가, 나중에 이어서 실행한다. 
    - 멈췄다가 이어서 실행할 수 있는 객체를 제너레이터라고 한다.
- @contextmanager: 표준 라이브러리 contextlib에 들어 있는 데코레이터. with는 원래 "시작할 때 할 일"과 "끝날 때 할 일"이 정의된 특별한 객체에서 쓸 수 있는데, 해당 데코레이터를 함수 위에 붙이면, yield로 반으로 나눈 평범한 함수를 with에서 쓸 수 있게 만들어준다.

4. Chain of Thought, CoT 생각의 사슬
- AI가 답하기 전에 풀이 과정을 직접 쓰게 만드는 기법이다. 사용자의 질문에 "생각 과정을 먼저 쓰라"는 지시가 들어있다.
- 바로 결론부터 쓰게 하면 계산하거나 따져 볼 공간 없이 첫 토큰에서 답을 찍어야 해서 틀리기 쉽다.
- 풀이를 먼저 쓰게 하면 중간 과정으로 쓴 토큰들이 다음 토큰 예측의 재료가 된다. 쓰면서 생각하는 효과이다.


#### Function Calling
- GPT는 원래 텍스트를 읽고 텍스트를 쓰는 기능만 가능하다. 이것을 해결해 다양한 작업을 가능하게 해주는 방법이 Function Calling(Tool Calling)이다.
**AI는 함수를 직접 실행하지 않는다. "이 함수를 이런 값으로 실행해 줘"라는 요청서를 쓴다. 실행은 파이썬 코드가 한다.**
- 모델이 파이썬 코드를 이해하려면 JSON 구조화 출력을 해야 모델이 읽고 실행할 수 있다.
> Function Calling 전체 흐름
> 1. 서비스 목록 전달
> 2. AI가 판단: 도구가 필요하면 -> 텍스트 대신 "도구 요청서" 반환
> 3. 파이썬에서 실행: 요청서대로 함수 실행 -> 결과를 AI에게 돌려준다.
> 4. AI가 최종 답변: 결과를 보고 사람이 읽을 문장으로 답한다.

- AI가 만든 요청서도 검증 없이 믿으면 안 되는 데이터다. 허용한 것만 실행시킬 수 있게 예외처리를 해야한다.
- 도구를 쓸지 말지의 판단은 서버의 AI 모델이 판단한다.
- 모델은 입력(JSON 포함)을 읽고, 응답으로 텍스트 또는 도구 호출 요청서를 생성한다. 요청서는 모델이 직접 실행하지 않고, 파이썬이 읽고 함수를 실행한 뒤 결과를 다시 API로 보낸다.
